# 002 - What Is MCP? (Model Context Protocol)

## Section

Converting Figma Designs to Code with Cursor + Figma MCP

## Duration

1:35

## Main Idea

Introduces MCP by name and points to the official site (modelcontextprotocol.io) as the canonical
place to learn the spec and SDKs. MCP was originally created by the team behind Claude 3.5 Sonnet
at Anthropic, and while the host isn't sure "open source" is the exact right label, the SDKs and
spec are publicly available on GitHub. The core definition: MCP standardizes how applications
provide context to LLMs. The host's favorite analogy is that MCP is like USB-C — a single
standardized connector that plugs into anything, letting one MCP client work with many different
MCP servers instead of needing a bespoke integration for every tool. By the end of the lesson,
learners should be able to state in one sentence what MCP standardizes and why that matters more
than it might first appear.

## Key Topics Mentioned

* MCP = Model Context Protocol
* Official spec/SDKs at modelcontextprotocol.io, created by the Claude 3.5 Sonnet team at
  Anthropic
* Core definition: MCP standardizes how applications provide context to LLMs
* USB-C analogy: one standard connector that works across many devices and peripherals
* Why context quality matters: good context → good output (e.g. a faithful Figma-to-React
  conversion); bad/missing context → poor or wrong output

## Review Questions

1. What is the main purpose of "What Is MCP?" in the context of Converting Figma Designs to Code
   with Cursor + Figma MCP?
2. Why is "USB-C for AI" a useful mental model for MCP?
3. How does the quality of context provided to an LLM affect a task like Figma-to-code conversion?
4. What risk or limitation should you keep in mind when an AI tool lacks proper context via MCP?

## Summary

Defines MCP as a standardization layer for feeding context to LLMs, illustrated with the USB-C
analogy, and ties context quality directly to output quality using the Figma-to-code use case as
the running example. This lesson is one building block toward the section's goal: giving learners
the conceptual vocabulary needed before the architecture and hands-on setup lessons that follow.
