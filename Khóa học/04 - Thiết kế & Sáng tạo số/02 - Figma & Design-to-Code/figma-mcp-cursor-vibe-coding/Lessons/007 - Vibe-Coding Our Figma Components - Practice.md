# 007 - Vibe-Coding Our Figma Components

## Section

Vibe-Coding Figma Design System Components with Cursor & Figma MCP

## Duration

3:22

## Main Idea

Walks through generating the actual React components once the token architecture is documented
and the demo button selection link is ready. The prompt explicitly references the shared
understanding of the design-token architecture built earlier, asks Cursor to build initial design
system components in React, states a preference to be able to test components as they're built,
and passes the Figma link scoped to the button selection. Cursor scaffolds a full project, after
which dependencies still need to be installed and a dev server started (a new terminal, `npm
install`, then `npm run dev`) before anything can be previewed. By the end of the lesson, learners
should see how Vibe-Coding Our Figma Components connects to the previous token work, since the
generated buttons should consume the token files built earlier rather than new hardcoded values.

## Key Topics Mentioned

* Prompting with prior context (token architecture) plus a scoped Figma component link
* Requesting React output that can be tested/previewed as it's built
* Cursor scaffolding a full project structure and files
* Installing dependencies (`npm install`) and starting a dev server (`npm run dev`) in a new terminal

## Summary

Walks through prompting Cursor to build React button components from the scoped Figma selection
link, using the previously documented token architecture as context, then installing dependencies
and starting a local dev server to make the result testable. This lesson is one building block
toward the section's goal: teaching how to connect Cursor to Figma via the Figma MCP server, feed
AI the right design-token context, and vibe-code initial React design system components that stay
wired to Figma variables.
