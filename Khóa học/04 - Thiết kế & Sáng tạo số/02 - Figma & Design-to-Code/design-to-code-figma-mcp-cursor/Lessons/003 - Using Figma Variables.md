# 003 - Using Figma Variables

## Section

Module 2: Preparing the Figma File for AI and MCP

## Duration

1:35

## Main Idea

Walks through why (and where) to use Figma Variables across the design: typography (font size,
line height), corner radius, spacing (padding, gap), and core colors. The rule of thumb given is
simple — anywhere a number shows up in the design, it should be backed by a variable, not a
hardcoded value. The presenter demonstrates this live by clicking through the app name text
(typography variables), corner radius on cards, and padding/gap values, then the main color
palette. A companion video on the channel (and the demo file itself, linked in the video
description) covers how to actually set these variables up.

## Key Topics Mentioned

* Typography variables: font size, line height
* Corner radius variables
* Spacing variables: padding, gap
* Color variables for primary/brand colors
* Rule of thumb: every numeric design value should be a variable
* Pointer to a separate channel video for full variable/design-system setup

## Review Questions

1. What is the rule of thumb for deciding whether a given design value needs a variable?
2. List the five categories of variables called out in this lesson (color, typography, spacing,
   radius, and one more).
3. Why would hardcoded numbers (instead of variables) make it harder for an AI tool to keep a
   design system consistent across multiple screens?

## Summary

Demonstrates live, inside the demo Figma file, how variables are applied to typography (size,
line height), corner radius, spacing (padding, gap), and core colors. The core principle: every
number in the design should trace back to a variable, because that consistency is what lets an AI
tool reproduce (and later extend) the design system reliably.
