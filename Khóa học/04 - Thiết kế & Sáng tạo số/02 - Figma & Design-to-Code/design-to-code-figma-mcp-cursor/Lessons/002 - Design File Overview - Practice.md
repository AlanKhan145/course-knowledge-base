# 002 - Design File Overview

## Section

Module 2: Preparing the Figma File for AI and MCP

## Duration

0:35

## Main Idea

A quick tour of the pre-built Figma file used for the demo. It contains a single main screen — a
wallet dashboard — plus one component that toggles between a "Main Card" view and a "Bitcoin
Wallet" view. That toggle is wired up as a Figma prototype interaction, but the presenter is
explicit that the prototype itself is not what matters for MCP. What matters is the underlying
layout structure and the design variables, which are covered in the next two lessons.

## Key Topics Mentioned

* One primary screen: the wallet dashboard
* One component with two states: Main Card and Bitcoin Wallet
* The prototype (click-through interaction) already exists in Figma
* Prototype interactions are not the important part for MCP/AI hand-off
* Layout structure and variables are what actually matter

## Review Questions

1. Why doesn't the Figma prototype (the click-through wiring) matter much for the MCP workflow?
2. What two things does the presenter say actually matter when preparing a file for AI?
3. What is the difference between a component's "variant" (Main Card vs. Bitcoin Wallet) and its
   "prototype interaction" (the click transition between them)?

## Summary

Introduces the demo file: a single wallet dashboard screen with a Main Card / Bitcoin Wallet
toggle component, already prototyped in Figma. The key takeaway is a scope-setting one — the
prototype wiring is not what an AI/MCP workflow relies on; the design's layout structure and
variables are, which sets up Lessons 3 and 4.
