# 004 - Prompting Philosophy: Small Steps and Knowing Your Stack

## Section

From Figma to Cursor & Claude Code with MCP — Building Sidebling.com

## Duration

0:43

## Main Idea

Before writing the first real prompt, the instructor shares the mindset that shapes the entire
session: never try to capture an entire app in one giant prompt. Break the work down into the
smallest reasonable pieces instead. He also notes that, as a 25-year front-end developer and
designer, he already knows which tech stack he wants (Nuxt.js) — but for anyone unsure, the right
move is to ask the AI "what tech stack should I use for this?" as a separate, code-free question
before ever asking it to write code.

## Key Topics Mentioned

* Anti-pattern: one giant prompt to build the whole app
* Breaking work into small, individual, verifiable steps
* Asking the AI for tech-stack advice as a distinct, non-coding question
* Instructor's own prior stack decision: Nuxt.js

## Review Questions

1. What is the main purpose of this "small steps" philosophy in the context of AI-assisted coding?
2. How would you apply this when you don't already know what tech stack to pick?
3. What are the key ideas demonstrated in this lesson?
4. What risk or limitation comes from prompting an AI to "build the whole app" at once?

## Summary

Lays out the guiding principle for the rest of the session: decompose the build into small,
specific prompts rather than one massive request, and settle on a tech stack (or ask the AI to
help choose one) before asking for any code. This lesson is one building block toward the
section's goal of a controllable, debuggable AI-coding workflow rather than an opaque one-shot
generation.
