# 004 - Using Auto Layout Correctly

## Section

Module 2: Preparing the Figma File for AI and MCP

## Duration

1:08

## Main Idea

Argues that Auto Layout is just as critical as Variables, because it's the Figma feature that
tells an AI tool how the layout is actually structured. Auto Layout is described as functioning
like Flexbox in web development — when a design is sent through MCP to an AI app, Auto Layout is
what lets the AI correctly infer how elements should behave (fill vs. hug vs. fixed sizing), which
in turn produces more responsive generated code. The presenter demonstrates fixing an element that
was "stuck" instead of filling its container by switching its sizing behavior to Fill live in the
file.

## Key Topics Mentioned

* Auto Layout ≈ Flexbox in web development
* Fill / Hug / Fixed sizing behaviors
* Auto Layout should be used on all major layout containers
* Correct Auto Layout usage → more responsive generated code
* Live fix: switching a "stuck" element to Fill sizing

## Review Questions

1. What web-development concept is Auto Layout compared to, and why is that comparison useful when
   thinking about AI-generated code?
2. What are the three sizing behaviors mentioned, and when would you use each one?
3. In the live example, what visual symptom indicated the element needed to be switched to Fill?

## Summary

Establishes Auto Layout as the second pillar (alongside Variables) of an MCP-ready Figma file.
Because Auto Layout behaves like Flexbox, using it consistently — with the right Fill/Hug/Fixed
settings — lets an AI coding tool correctly interpret layout intent and produce responsive code
instead of guessing at structure.
