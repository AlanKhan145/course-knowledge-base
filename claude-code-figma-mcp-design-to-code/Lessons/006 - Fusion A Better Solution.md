# 006 - Fusion: A Better Solution

## Section

Claude Code + Figma MCP Server for Design to Code

## Duration

0:41

## Main Idea

Introduces Builder.io's diagnosis of why the Claude Code + Figma MCP workflow hits the limitations
described in the previous lesson: all four issues trace back to one root cause — forcing a visual,
collaborative design process into a single-player, text-based workflow. Their response is Fusion, a
tool that reimagines design-to-code as a visual experience that generates code, rather than a
prompt-driven, one-shot text pipeline. Instead of recreating a component's code from scratch on
every change, Fusion is described as actually understanding the underlying design system: when you
sync changes from Figma, it updates only the visual properties, while the project's React logic,
`useState` hooks, and API calls remain untouched. The lesson closes by revisiting the earlier
multi-frame/carousel limitation — in Fusion, you can drop all the relevant frames in at once and ask
it to assemble them into a carousel directly.

## Key Topics Mentioned

* Root-cause framing: visual/collaborative design work forced into a single-player text workflow
* Fusion positioned as a visual design-to-code editor, not a prompt-to-code generator
* Syncing Figma changes updates only visual properties, preserving React logic/state/API calls
* Revisiting the carousel/multi-frame limitation as something Fusion handles directly

## Summary

Argues that the Claude Code + Figma MCP limitations all stem from squeezing a visual,
collaborative process into a single-player text workflow, and introduces Fusion as Builder.io's
answer: a visual design-to-code editor that understands the design system well enough to update
only visual properties on sync, leaving application logic untouched. This lesson pivots the video
from demoing Claude Code's limitations to pitching Fusion as the alternative, explored further in
the next lesson.
